1. QUÉ SE DEBE CONSTRUIR (LECTURA DEL PDF)
================================================================================

OBJETIVO DE ANALÍTICA — responder estas 4 preguntas:
  1. Número de canciones vendidas por día
  2. Artista más vendido por mes
  3. Día de la semana con más compras
  4. Mes con mayor número de ventas

MODELO ESTRELLA (desnormalización de la BD transaccional Chinook):

  ┌─────────────────────────────────────┐
  │  FactSales                          │
  │  ───────────────────────            │
  │  CustomerKey      (FK → DimCustomer)│
  │  TrackKey         (FK → DimTrack)   │
  │  InvoiceDateKey   (FK → DimDate, yyyymmdd int)
  │  EmployeeKey      (FK → DimEmployee)│
  │  Quantity                           │
  │  UnitPrice                          │
  │  TotalAmount                        │
  └─────────────────────────────────────┘

  DimCustomer        DimTrack           DimEmployee (*)    DimDate
  ───────────────    ───────────────    ──────────────     ─────────────
  CustomerKey PK     TrackKey PK        EmployeeKey PK     DateKey PK (yyyymmdd)
  FirstName          Name               FirstName          FullDate
  LastName           Album              LastName           Year
  Company            Artist             Title              Quarter
  Country            Genre              ReportsTo          Month
  City               MediaType          ...                Day
  State              Composer                              DayOfWeek
  Email              Milliseconds                          IsHoliday

  (*) El PDF menciona "EmployeeKey" en FactSales y exige ETL full copy con
      histórico de "a quién le reporta cada empleado" → implica DimEmployee
      con campo ReportsTo (auto-referencia).

REQUISITOS TRANSVERSALES DEL PDF:
  - Almacenamiento: S3 + Athena, particionado por año/mes/día
  - ETLs:
      · DimCustomer, DimTrack, FactSales → Glue VISUAL
      · DimEmployee full copy (histórico ReportsTo)
      · DimDate → script Python con paquete "holidays"
  - ETLs deben mantener datos sincronizados con el Parcial 1 (sistema OLTP)
  - Presentación: Power BI conectado a AWS Athena
  - Toda la arquitectura con CI/CD + pruebas unitarias
  - Los jobs son archivos en S3 — creados/actualizados vía boto3

FASE 3 — FactSales ETL (el más complejo de todos los ETLs)
  Archivo: /etl/glue_jobs/fact_sales_etl.py
  Source: RDS "invoice" + "invoice_line"
  Joins necesarios:
    - invoice_line INNER JOIN invoice ON invoice_id
    - invoice LEFT JOIN customer ON customer_id
    - customer LEFT JOIN employee ON support_rep_id (→ EmployeeKey)
    - track_id viene directo de invoice_line
  Cálculos:
    - InvoiceDateKey = int(year*10000 + month*100 + day) desde invoice_date
    - TotalAmount = unit_price * quantity
  Columnas finales del parquet:
    CustomerKey, TrackKey, InvoiceDateKey, EmployeeKey,
    Quantity, UnitPrice, TotalAmount
  Particionamiento físico en S3:
    s3://.../fact_sales/year=2026/month=04/day=15/*.parquet
  Estrategia incremental:
    - Activar Glue Job Bookmark en el job
    - Bookmark se apoya en invoice.invoice_date
    - En cada ejecución solo procesa facturas nuevas
  Build en Glue Studio:
    - Visual mode con Source JDBC → Join Nodes → SQL Transform para
      derivar InvoiceDateKey → Target S3 con partitioning
    - Exportar script Python → commit a /etl/glue_jobs/fact_sales_etl.py

7. CRITERIOS DE ACEPTACIÓN POR COMPONENTE
================================================================================

FactSales ✓ cuando:
  - Athena query "SELECT COUNT(*) FROM fact_sales" retorna > 0
  - Particiones visibles en S3 (year=2026/month=04/day=15/*.parquet)
  - Hacer una compra en la app frontend → aparece en Athena en ≤ 30min

DimDate ✓ cuando:
  - Athena query "SELECT IsHoliday FROM dim_date WHERE DateKey=20261225"
    retorna TRUE
  - Cubre rango 2009-2030 sin huecos

DimCustomer ✓ cuando:
  - COUNT coincide con COUNT en RDS customer (59 en Chinook base + nuevos)
  - Registrar usuario en la app → aparece en DimCustomer en ≤ 30min

DimEmployee ✓ cuando:
  - Todos los empleados presentes
  - Reports_to funciona (manager hierarchy consultable)
  - Histórico en dim_employee_history/snapshot_date=...

Pipeline CI/CD ✓ cuando:
  - Push a main → tests pasan → scripts suben a S3 → Glue jobs actualizados
  - Sin intervención manual

Power BI ✓ cuando:
  - Los 4 dashboards cargan datos reales desde Athena
  - Al refrescar datos, se actualiza con los últimos registros del RDS

8. CONSIDERACIONES AWS ACADEMY (IMPORTANTE)
================================================================================

EL EQUIPO COMPARTE UNA SOLA CUENTA ACADEMY:

Esto cambia varias cosas y hay que coordinarse:

  1. NO PODEMOS crear IAM users ni IAM roles nuevos
     → Usar "LabRole" en todo (Glue jobs, ejecución, etc.)
     → La policy del LabRole ya tiene permisos amplios en Academy

  2. TODAS las credenciales son compartidas entre los 3
     → Desde el Learner Lab → "AWS Details" → Show → copiar:
         · AWS_ACCESS_KEY_ID
         · AWS_SECRET_ACCESS_KEY
         · AWS_SESSION_TOKEN
     → Rotan cada 4h — cuando uno inicia sesión, los anteriores mueren
     → Compartirlas en un medio seguro (1Password, mensaje directo, etc.)

  3. RIESGO: dos personas editando el mismo Glue Job al mismo tiempo
     → Coordinar en chat: "estoy editando DimCustomer" antes de entrar
     → Los scripts exportados al repo son la "source of truth"

  4. CI/CD con Academy es limitado:
     → Los secrets de GitHub Actions deben actualizarse manualmente
       cada vez que rotan las credentials (cada 4h)
     → RECOMENDACIÓN: workflow con "workflow_dispatch" (trigger manual)
       para el deploy, y automático solo para los tests

  5. Créditos limitados:
     → No correr ETLs cada 5 min → mejor cada 30-60 min
     → Apagar Glue Jobs cuando no se está probando
     → Revisar periódicamente el uso en el dashboard del Learner Lab

  6. Servicios disponibles en Academy: S3, Glue, Athena, RDS, EC2 ✅
     Servicios NO disponibles (típicamente): IAM user creation, Secrets
     Manager completo, algunos servicios enterprise

  7. Elastic IPs ya usadas del Parcial 1 siguen válidas — no liberarlas

PROTOCOLO DE COORDINACIÓN DEL EQUIPO:

  Canal de Slack/WhatsApp del proyecto:
  - Anunciar "entrando a AWS Console" antes de cualquier edit
  - Anunciar "nueva sesión Lab iniciada" si rota el token (todos deben
    actualizar sus ~/.aws/credentials)
  - Anunciar "subiendo a S3 vía CI/CD" antes de dispatch manual

  Archivo local por persona: ~/.aws/credentials
  Formato:
    [default]
    aws_access_key_id = ASIA...
    aws_secret_access_key = ...
    aws_session_token = ...

  Para rotar:
  1. Ir a Learner Lab → "AWS Details" → Show AWS CLI
  2. Copiar las 3 líneas
  3. Pegar en ~/.aws/credentials (reemplazar)
  4. Avisar al equipo que se rotó

PROBLEMAS CONOCIDOS:
  - Glue Connection a RDS falla si SG-RDS no permite subnet del Glue
    → Fix: agregar regla inbound 5432 desde el mismo SG
  - Athena requiere output location S3 — crear carpeta antes
  - Power BI Desktop solo en Windows/Mac — usar VM si están en Linux
  - Glue Bookmarks NO funcionan si invoice_date cambia retroactivamente
